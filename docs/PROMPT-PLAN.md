## 1. 你原来的提示词，问题在哪

原文（一字没改）：

> 你现在评价下这个loom agent项目，认真评价不要给我面子，不要有安慰我的语气，并且分析根据agent=model+harness的设计思路，来帮我分析如何改进这个项目，使得其不仅是页面并且功能上设计要按照工程化，并且能完整调用和自行调用子agent一起开发完成需求设计。具体的功能按照deepseekharness的基础逻辑来设计，也可以自行添加插件，并且添加的难度和整体的设计简易并且符合一般使用逻辑，设计完成度达到60%来告诉我让我进行自测和评估，其他时间你全部自行处理，并且跟进开发文档和设计文档的思路，在后面同步更新readme。

**九个诉求揉在一句话里，而且没有优先级。** 逐条看：

| # | 问题 | 后果 |
|---|---|---|
| 1 | 「不要给我面子」是态度要求，没给**评价维度** | 模型会挑好说的说；得点名按什么评（工具协议／计量／上下文／测试…） |
| 2 | 「不仅是页面」四个字太虚 | 没说清什么叫「不只是页面」。真正的问题是这个项目的**能力造在 core、产品够不着** |
| 3 | 「按 deepseek harness 的基础逻辑」**没给参照物** | 模型只能凭印象编「DSH 大概是…」。实际上 DSH 就装在本机，路径可以写死 |
| 4 | 「60% 完成度」没有**验收口径** | 60% 按什么算？行数？功能数？最后只能互相猜 |
| 5 | 「你全部自行处理」和 AGENTS.md 的「先计划后编码」**冲突** | 到底先给方案还是直接干，没讲清 |
| 6 | 没给**项目路径**、没给**硬约束** | 加依赖、破坏离线能力这些事，模型不会自己知道 |
| 7 | 「完整调用和自行调用子 agent」有歧义 | 是「用子 agent 去开发」还是「让 loom 这个产品能派子 agent」？其实你要的是后者 |

## 3. 子进程怎么拆

拆分原则：**按文件边界拆，不按功能阶段拆。** 同一时刻两个进程不碰同一个文件。

| 进程 | 产出文件 | 为什么能独立 |
|---|---|---|
| **P-compact** | `src/loop/compact.ts`、`test/compact.test.mjs` | 只依赖 `ai` 的 `generateText`；接口（`compactHistory`）先定死，谁都不需要读实现 |
| **P-plugins** | `src/plugins/types.ts`、`registry.ts`、`test/plugins.test.mjs`、`plugins/hello-plugin/*` | 全新的目录，零改动既有文件 |
| **P-todo** | `src/plan/todo.ts`、`test/todo.test.mjs` | 全新文件；`TODO_WRITE_SCHEMA` 与四条错误文案在任务书里逐字给定 |
| **主线程（我）** | `types/index.ts`、`loop/run.ts`、`tools/catalog.ts`、`tools/cmd.ts`、`agents/subagents.ts`、`agents/profiles.ts`、两个 API 路由、`LoomShell.tsx` | 全是**既有文件的改动**，互斥，不能并行 |

**接口先定死再派人**——三个子进程的任务书里，导出名、类型名、错误文案都是逐字给的。
不这么做的话，三天后合并时对不上，返工的比省下来的多。

**实测结果**：三个子进程全部中途挂了（网络断 + 上下文耗尽），但 compact 和 plugins 的产物**落盘了且可用**，
todo 一个字节没写出来。→ **教训：子进程不适合派「要写 200 行以上、且接口依赖另一份未落地文件」的活。**
它挂了不留 closing message，你不知道停在哪，只能读磁盘对账。todo 那部分最后是我自己补的。

## 5. 复盘：这份拆分哪里对、哪里错

**对的**：
- **按文件边界拆** —— 三个子进程从头到尾没互相踩过，合并时零冲突。
- **接口先定死** —— compact 挂掉后它的产物能被 `run.ts` 直接接上，就是因为签名是事先给的。
- **主线程自己啃既有文件** —— 这部分串行是对的，三个子进程的任务书加起来也没它改得多。

**错的**：
- **把 todo 派出去了** —— 它要写 254 行且依赖会话概念，最该留给主线程。子进程挂了就是零产出。
- **备份做在动手前一刻** —— 应该是 `git init` 而不是拷文件。8 个快照目录现在散在 `docs/_snapshot/` 下，
  这是负债，不是资产（已写进 P2 第一件事）。
- **没先要求子进程回报进度** —— 它挂了我才知道，中间 40 分钟是黑盒。

**如果重来一次**：三个子进程的活里，只有 plugins（全新目录、契约简单）真正适合外包；
compact 和 todo 应该主线程自己写，把省下的协调成本花在 UI 接线上。
